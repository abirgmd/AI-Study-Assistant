Une page web repose sur trois technologies complémentaires : HTML décrit la structure du contenu, CSS gère la présentation visuelle et JavaScript ajoute l'interactivité côté navigateur.
Les balises sémantiques HTML5 comme header, nav, main, article et footer décrivent le rôle de chaque zone de la page. Elles améliorent l'accessibilité pour les lecteurs d'écran et le référencement par les moteurs de recherche.
Le modèle de boîte CSS considère chaque élément comme un rectangle composé du contenu, du padding, de la bordure et de la marge. La propriété box-sizing border-box simplifie le calcul des dimensions.
Flexbox dispose les éléments sur un seul axe, en ligne ou en colonne, et répartit l'espace disponible avec justify-content et align-items. Il convient parfaitement aux barres de navigation et aux alignements simples.
CSS Grid crée des mises en page à deux dimensions en définissant des lignes et des colonnes. Les zones nommées avec grid-template-areas rendent la structure d'une page lisible directement dans la feuille de style.
Le responsive design adapte l'affichage à toutes les tailles d'écran grâce aux media queries, aux unités relatives et aux images flexibles. L'approche mobile first commence par concevoir la version pour smartphone.
Le DOM représente le document HTML sous forme d'arbre d'objets manipulable en JavaScript. Les méthodes querySelector, createElement et addEventListener permettent de modifier la page sans la recharger.
Les promesses et la syntaxe async await simplifient le code asynchrone en JavaScript. Une requête fetch vers une API retourne une promesse que l'on attend avant de traiter la réponse JSON.
Une API REST expose des ressources identifiées par des URL et manipulées avec les verbes HTTP GET, POST, PUT, PATCH et DELETE. Les codes de statut comme 200, 201, 404 ou 422 indiquent le résultat de chaque requête.
Le format JSON représente les données échangées entre le navigateur et le serveur sous forme d'objets, de tableaux, de chaînes et de nombres. Il est léger, lisible et nativement compris par JavaScript.
React construit l'interface à partir de composants réutilisables qui reçoivent des props et gèrent un état local. Lorsque l'état change, React recalcule le rendu et met à jour uniquement les parties modifiées du DOM.
Les hooks de React, comme useState et useEffect, permettent aux composants fonctionnels de gérer un état et des effets de bord, par exemple charger des données depuis une API au montage du composant.
Vue.js propose des composants monofichiers regroupant le gabarit, le script et le style. Sa réactivité suit automatiquement les dépendances des données et met à jour l'affichage lorsqu'elles changent.
Angular est un framework complet écrit en TypeScript, qui fournit l'injection de dépendances, le routage, les formulaires réactifs et un outil en ligne de commande pour générer composants et services.
Node.js exécute du JavaScript côté serveur grâce au moteur V8. Son modèle à boucle d'événements non bloquante gère un grand nombre de connexions simultanées avec peu de ressources.
Express est un framework minimaliste pour Node.js. On y déclare des routes associées à des fonctions de traitement et des middlewares qui interceptent les requêtes pour l'authentification, la journalisation ou l'analyse du corps.
Django est un framework web Python qui suit le motif modèle, vue, gabarit. Il fournit un ORM, une interface d'administration générée automatiquement et des protections intégrées contre les attaques CSRF.
Flask est un micro-framework Python qui laisse le développeur choisir ses extensions. Une application minimale tient en quelques lignes : on crée l'application, on décore une fonction avec une route et on retourne la réponse.
Le PHP s'exécute sur le serveur et génère du HTML envoyé au navigateur. Les sessions conservent l'état de l'utilisateur entre les requêtes, et l'extension PDO offre un accès sécurisé aux bases de données.
Les cookies sont de petits fichiers stockés par le navigateur et renvoyés au serveur à chaque requête. Les attributs HttpOnly, Secure et SameSite protègent les cookies de session contre le vol et les requêtes intersites.
L'authentification par jeton JWT transmet un jeton signé contenant l'identité de l'utilisateur. Le serveur vérifie la signature à chaque requête sans conserver de session, ce qui facilite la mise à l'échelle des API.
La validation des formulaires doit se faire côté client pour le confort de l'utilisateur, mais toujours être répétée côté serveur, car un attaquant peut contourner le navigateur et envoyer des données arbitraires.
CORS est le mécanisme par lequel un serveur autorise un site d'une autre origine à appeler son API depuis le navigateur. Une configuration trop permissive avec un astérisque expose l'API à n'importe quel site.
Le rendu côté serveur génère le HTML complet avant de l'envoyer, ce qui accélère le premier affichage et facilite le référencement. Next.js et Nuxt combinent rendu serveur et interactivité côté client.
Une application monopage charge une seule page HTML puis met à jour le contenu dynamiquement en JavaScript. Le routage côté client modifie l'URL sans rechargement complet du navigateur.
TypeScript ajoute un typage statique à JavaScript. Les erreurs de type sont détectées à la compilation, l'autocomplétion de l'éditeur devient plus précise et les grandes bases de code sont plus faciles à maintenir.
Les outils de construction comme Vite ou Webpack regroupent les modules JavaScript, transpilent le code moderne, minifient les fichiers et optimisent les images pour réduire le temps de chargement en production.
npm gère les dépendances d'un projet JavaScript déclarées dans le fichier package.json. Le fichier package-lock.json fige les versions exactes installées pour que toute l'équipe utilise les mêmes bibliothèques.
L'accessibilité web vise à rendre les sites utilisables par tous, y compris les personnes en situation de handicap. Textes alternatifs des images, contraste suffisant et navigation au clavier font partie des critères WCAG.
Les performances d'un site se mesurent avec les Core Web Vitals : temps d'affichage du plus grand élément, réactivité aux interactions et stabilité visuelle de la mise en page pendant le chargement.
Le chargement différé des images, ou lazy loading, ne télécharge une image qu'au moment où elle approche de la zone visible. Il réduit le poids initial de la page, particulièrement sur mobile.
Une progressive web app peut être installée sur l'écran d'accueil et fonctionner hors ligne grâce à un service worker qui met en cache les ressources et intercepte les requêtes réseau.
GraphQL permet au client de demander exactement les champs dont il a besoin en une seule requête. Il évite les allers-retours multiples et les données superflues d'une API REST classique.
Les WebSockets établissent une connexion bidirectionnelle persistante entre le navigateur et le serveur. Ils conviennent aux applications temps réel comme les messageries instantanées ou les tableaux de bord en direct.
Le référencement naturel améliore la position d'un site dans les résultats des moteurs de recherche grâce à des titres pertinents, des balises meta descriptives, des URL lisibles et un contenu de qualité.
Exercice : réalisez une page d'inscription en HTML et CSS responsive, ajoutez une validation JavaScript des champs e-mail et mot de passe, puis envoyez les données à une API Express qui renvoie un code 201.
Les préprocesseurs CSS comme Sass ajoutent des variables, l'imbrication des règles et des mixins. Les propriétés personnalisées CSS natives permettent aujourd'hui de définir des variables de thème modifiables à l'exécution.
Le déploiement d'une application web peut s'appuyer sur un hébergement statique pour le front-end et sur un serveur ou une plateforme cloud pour l'API. Un nom de domaine et un certificat HTTPS complètent l'installation.
Les variables d'environnement stockent la configuration d'une application web, comme l'adresse de la base de données ou les clés d'API. Elles ne doivent jamais être commitées dans le dépôt Git.
Le moteur de gabarits, comme Twig, Jinja ou EJS, insère des données dynamiques dans des pages HTML. Il échappe automatiquement les variables affichées pour prévenir les failles de type XSS.
La gestion d'état global d'une application front-end peut s'appuyer sur Redux, Pinia ou le contexte React. Elle centralise les données partagées entre composants, comme l'utilisateur connecté ou le panier.
Les tests front-end combinent tests unitaires de composants avec Jest ou Vitest et tests de bout en bout avec Cypress ou Playwright, qui pilotent un vrai navigateur pour simuler les clics et les saisies.
Le protocole HTTPS chiffre les échanges entre le navigateur et le site. Les navigateurs signalent comme non sécurisés les formulaires envoyés en HTTP, et de nombreuses API du navigateur exigent une origine sécurisée.
La politique de sécurité du contenu, définie par l'en-tête Content-Security-Policy, indique au navigateur les sources autorisées pour les scripts, les styles et les images. Elle bloque l'exécution de scripts injectés.
Le téléversement de fichiers doit vérifier la taille, le type réel du contenu et renommer le fichier côté serveur. Un fichier PHP déposé dans un dossier public pourrait sinon être exécuté par un attaquant.
La pagination des résultats d'une API limite le nombre d'éléments renvoyés par requête grâce aux paramètres limit et offset ou à un curseur. Elle évite de transférer des milliers d'enregistrements inutiles.
Le modèle MVC sépare le modèle, qui gère les données, la vue, qui affiche l'interface, et le contrôleur, qui reçoit les requêtes et orchestre les deux. Laravel et Symfony appliquent ce modèle en PHP.
Laravel fournit un routage expressif, l'ORM Eloquent, des migrations de base de données et un système de files d'attente. Sa ligne de commande Artisan génère contrôleurs, modèles et tests en une instruction.
Les animations CSS avec transition et keyframes animent les changements de propriétés sans JavaScript. Il est préférable d'animer transform et opacity, que le navigateur peut accélérer avec la carte graphique.
La documentation d'une API avec OpenAPI décrit chaque route, ses paramètres, ses corps de requête et ses réponses. Des outils comme Swagger UI en génèrent une page interactive pour tester les appels.
TP : développez une application de liste de tâches avec un front-end React et une API Node.js. Les tâches sont stockées dans une base, et l'interface permet d'ajouter, cocher et supprimer une tâche.
Le stockage local du navigateur, avec localStorage, conserve des données simples entre les visites. Il ne doit pas contenir de jetons d'authentification sensibles, accessibles à tout script exécuté sur la page.
Les formulaires accessibles associent chaque champ à une étiquette avec l'attribut for, regroupent les options liées dans un fieldset et annoncent les erreurs de validation de manière perceptible par les technologies d'assistance.
Le cache HTTP réduit les téléchargements répétés grâce aux en-têtes Cache-Control et ETag. Les fichiers statiques versionnés peuvent être mis en cache pendant un an, tandis que les pages dynamiques restent fraîches.
Un framework CSS comme Bootstrap ou Tailwind accélère la création d'interfaces cohérentes. Tailwind propose des classes utilitaires combinées directement dans le HTML plutôt que des composants préconçus.
Le shadow DOM des Web Components encapsule la structure et les styles d'un composant personnalisé. Les styles de la page ne fuient pas à l'intérieur du composant et inversement.
Les middlewares d'une application Express s'exécutent dans l'ordre de leur déclaration. Un middleware de gestion d'erreurs, déclaré en dernier, centralise la transformation des exceptions en réponses JSON propres.
Le versionnage d'une API web, par exemple avec un préfixe v1 dans l'URL, permet de faire évoluer les réponses sans casser les applications clientes qui utilisent encore l'ancienne version.
La conception d'interface commence souvent par des maquettes fil de fer puis des prototypes interactifs réalisés dans Figma. On valide le parcours utilisateur avant d'écrire la moindre ligne de code front-end.
Le rendu d'une liste en React exige une clé unique et stable pour chaque élément. Utiliser l'index du tableau comme clé provoque des bugs d'affichage lorsque l'ordre des éléments change.
Les serveurs web Apache et Nginx servent les fichiers statiques et transmettent les requêtes dynamiques à PHP-FPM ou à une application Node.js. Leur configuration définit les hôtes virtuels, la réécriture d'URL et la compression.
